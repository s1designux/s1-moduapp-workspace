어떤 유형의 화면에서 어떤 부품을 주로 쓰는지 정리한다. 늘 함께 붙어 다니는 부품 조합(부품 묶음)도 찾아 표로 정리한다.

## 단계
1. 📋 **유형 나누기**: 화면 270개를 두 축으로 나눈다.
   - 화면 모양: 세로 기본 / 가로 확대 × 단일채널 / 다채널. iOS 가로(874×402)와 폴드(476×752)는 따로 표시한다.
   - 화면 상태: 기본 · 버튼 뜬 상태(딤) · 바텀시트 열림 · 가운데 팝업 · 오른쪽 패널 · 토스트 · 영상 안 나옴(수신불량·카메라 없음·신호 없음) · 빈 화면.
2. 🧩 **부품 세기**: 유형마다 어떤 부품이 몇 화면에 쓰였는지 센다. 두 가지 기록을 같이 쓴다.
   - Figma 부품 기록(instance 이름 → `video-v2-components.json`의 쉬운 이름으로 바꿔서)
   - 화면을 눈으로 보고 적은 기록(`components`)
   - 둘이 다르면 차이를 표시한다.
3. 🔗 **부품 묶음 찾기**: 거의 항상 함께 나오는 조합을 찾아 이름을 붙인다.
   - 예: "상단 현장 헤더 + 실시간/녹화 칩 + 영상 칸 + 하단 탭바", "딤 + 상단 툴바 + 원형 버튼 줄"
   - 묶음마다 어느 유형에서 쓰이는지 적는다.
4. ✅ **눈으로 확인**: 유형마다 대표 화면 1~2개를 Figma 스크린샷으로 다시 보고, 센 결과와 맞는지 대조한다.
   - 스크린샷은 하루 호출 한도가 있으니 대표 화면만 찍는다.
5. 📄 **결과 저장**: `outputs/moduapp/service-video/` 아래에 둔다.
   - `video-v2-screen-type-components.json`: 유형 × 부품 표, 부품 묶음 목록
   - `video-v2-screen-type-components.html`: 유형별 대표 화면 그림과 사용 부품·묶음 표. river가 눈으로 대조할 수 있게 만든다.
   - 끝나면 이 파일의 상태를 "완료"로 바꾸고 커밋 → GitHub에 올린다.

## 주의
- Figma 프레임명은 엉터리다. 화면 이름은 캡션과 실제 화면 기준으로 정한다. 기존 분석의 `label_actual`과 `caption`을 쓴다.
- 녹화영상 가로 두 열은 Figma에 "기본"으로 적혀 있지만 실제로는 "확대"다. 기존 분석이 이미 바로잡아 두었다.
- 확신 없는 건 `needs_review`로 남긴다.
